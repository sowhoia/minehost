# mine-host — дизайн

Дата: 2026-06-10. Статус: утверждён пользователем.

## Проблема

Чтобы поиграть с друзьями в Minecraft по сети, сегодня нужно либо арендовать сервер, либо соединяться через Hamachi/Radmin VPN. VPN-сервисы гонят весь трафик через свои релей-серверы, которые могут находиться на другом конце света от обоих игроков, — отсюда высокий пинг и нестабильность. Для тяжёлых модпаков (400+ модов) проблема усугубляется большими объёмами трафика на этапе логина.

## Продукт

Кроссплатформенное (Windows/macOS/Linux) десктоп-приложение: «Hamachi для Minecraft, только молниеносный». Один игрок хостит мир на своём ПК (Open to LAN или собственный выделенный сервер), приложение P2P-туннелем доставляет мир друзьям так, что он появляется у них **в списке LAN-серверов** внутри Minecraft.

Принятые продуктовые решения:

| Решение | Выбор |
|---|---|
| Охват | Только сетевое ядро («Hamachi, только лучше»). Без синхронизации модпаков и управления сервером — игроки настраивают моды сами. |
| Инфраструктура | Ноль своих серверов. Iroh + бесплатная геораспределённая релей-сеть n0. Релей — только для установления соединения и fallback. |
| Интеграция с игрой | Локальный прокси без драйверов и прав администратора. Никаких TUN-адаптеров. |
| UI | Tauri 2 + Svelte, GUI с трей-иконкой. |

## UX

**Хост:** открыл приложение → «Хостить» → приложение само нашло открытый в LAN мир (или хост указал порт сервера вручную) → получил код приглашения → отправил друзьям в мессенджере.

**Гость:** вставил код → «Подключиться» → открыл Minecraft → Multiplayer → мир хоста уже виден в списке LAN → играет. Никаких IP, портов и настроек сети.

## Почему быстро и стабильно

- **Прямое соединение.** Hole punching через UDP (механизм Iroh, аналогичный Tailscale): после установления соединения трафик идёт напрямую между игроками, задержка = чистый RTT между провайдерами. Релей используется первые секунды и как fallback для строгих CGNAT (~10% случаев); апгрейд relay→direct происходит на лету без разрыва.
- **QUIC-транспорт.** TCP-трафик Minecraft пробрасывается через надёжные QUIC-потоки — нет проблемы TCP-over-TCP meltdown (двойного управления перегрузкой). Буферы и flow control рассчитаны на всплески в десятки МБ (синхронизация реестров модов при логине).
- **Живучесть.** Iroh переживает смену сети (Wi-Fi → кабель, смена IP) без разрыва QUIC-сессии. Поверх этого — автопереподключение туннеля с экспоненциальным backoff.
- **Шифрование.** NodeId — Ed25519-ключ, соединения шифрованы end-to-end; релей не может читать трафик.

## Архитектура

```
mine-host/
├── core/        Rust-библиотека: вся сетевая логика, без UI
└── app/         Tauri 2: Rust-обвязка + фронтенд (Svelte + Vite)
```

`core` не знает про UI и тестируется отдельно. `app` использует его через узкий API: `start_host`, `join`, поток событий статуса. Поверх `core` позже можно сделать CLI или встроить в лаунчер.

### core

- **Хост-сессия:** Iroh-эндпоинт принимает входящие QUIC-соединения; каждый входящий bidi-поток мапится на TCP-подключение к локальному порту Minecraft.
- **Автообнаружение порта:** Minecraft при «Open to LAN» анонсирует порт мультикастом на `224.0.2.60:4445` (формат `[MOTD]...[/MOTD][AD]port[/AD]`). Приложение слушает эти анонсы. Для выделенного сервера порт задаётся вручную.
- **Гость-сессия:** локальный TCP-листенер на `127.0.0.1:<порт>`; каждое подключение Minecraft открывает QUIC bidi-поток к хосту.
- **LAN-маяк гостя:** приложение само шлёт мультикаст-анонс на машине гостя, чтобы мир появился в списке LAN автоматически (имя мира берётся из MOTD хоста, помечается признаком туннеля).
- **Приглашение:** Iroh-тикет (NodeId + прямые адреса + релей), сериализованный в строку для копипасты.
- **UDP-проброс:** датаграммы для голосовых модов (Simple Voice Chat) через QUIC unreliable datagrams, маппинг порт-в-порт.

### app

Два экрана:

- **Хостить:** статус обнаруженного мира/сервера, крупный код приглашения + «Копировать», список подключённых: имя, пинг, индикатор «⚡ напрямую / 🌐 через релей».
- **Подключиться:** поле кода, статус соединения, подсказка «Открой Minecraft → Multiplayer», пинг/индикатор пути.

Трей-иконка (работа в фоне), системные уведомления о подключении друзей.

## Обработка ошибок

- Автопереподключение с экспоненциальным backoff; обрыв у любой стороны не убивает сессию.
- Диагностика человеческим языком вместо «connection failed»: «не вижу открытый в LAN мир — открой через Esc → Open to LAN», «работаем через релей — пинг выше обычного», «код приглашения недействителен/устарел».
- Падение Minecraft у хоста → гости видят «хост офлайн», туннель ждёт возвращения.

## Тестирование

- Unit: парсер/генератор LAN-анонсов (чистые функции); прокси через эхо-TCP-сервер в loopback.
- Интеграция: два Iroh-эндпоинта в одном процессе, цикл host → ticket → join → обмен данными → переподключение.
- Ручная проверка с реальным Minecraft в конце каждого этапа.

## Этапы

1. **Ядро:** Iroh-туннель host↔guest + тесты.
2. **Minecraft-интеграция:** автообнаружение LAN-порта, LAN-маяк гостя, тикеты.
3. **Tauri-приложение:** экраны Хостить/Подключиться, трей, события статуса.
4. **Полировка:** UDP для голоса, переподключение, диагностика, сборки под Win/macOS/Linux.

## Вне охвата (v1)

- Синхронизация модпаков между игроками.
- Запуск/управление Minecraft-сервером из приложения.
- Виртуальный сетевой адаптер (TUN) и поддержка других игр.
- Свои релей-серверы.
- Аккаунты/друзья/постоянные комнаты — только одноразовые коды-тикеты.
